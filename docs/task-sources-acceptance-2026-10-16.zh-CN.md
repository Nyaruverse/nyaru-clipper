## 功能

- 新建任务直接显示「实时录播／下载视频／本地视频」。直播输入数字房间号，下载输入 BV 号，界面不要求完整链接；后端生成规范地址。旧 HTTP(S) API 客户端继续兼容。
- 各来源草稿独立保留，未选中字段禁用以排除表单校验。直播固定使用现有实时臊子；切回视频恢复此前切片选项。
- 下载与本地视频共用指定时间段、高光、臊子三种处理方式；前两种无需 AI 配置。本地上传流式写入任务副本，原文件不修改。
- 新增 `POST /companion-api/jobs/upload`，复用已有上传、单任务限制、磁盘空间检查和清理；保留 `/saozi/upload`。无效切片设置先拒绝，空文件失败后可重新提交。

## 实际工作流

先在隔离目录用真实浏览器选择 11.2 秒合成视频，执行本地识别和 1–4 秒导出；随后通过最终冻结后端重复导入、识别与导出。两次均完成，冻结后端产生 3 条识别字幕；ffprobe 确认 3.000000 秒切片含音频与视频，源副本哈希一致，未使用现有任务或外部 AI。

原生安装版已观察三个入口，实际填写 BV 与房间号并清空示例；没有提交真实下载或直播任务。已有 20 个任务 ID、供应商／授权状态和数据目录原有文件保持一致；升级备份与哈希统计见交接。

## 界面检查与限制

初轮覆盖 10 个来源／切片状态、390／1440／1920 CSS 宽度及抽屉顶／底，共 60 张截图。修复了选中来源按钮被通用悬停背景覆盖、文字对比度不足的问题。用户随后要求界面只收编号，更新后另拍 1440／390 的直播与 BV 表单，并观察最终原生窗口。

浏览器工具只提供 CSS 视口；390 宽度不是完整触屏移动设备模拟。本轮未完成双外观、完整移动设备或独立严格视觉认证。产品继续使用现有浅色纸张主题。LSP 服务不可用，未安装；编译与上述测试通过。

真实 Bilibili 下载／长时直播、外部 AI 授权续期／撤销、全部视频格式和更多机器未重新验收。仍为 arm64、最低 macOS 27.0、本地签名未公证；源码推送不等于公开分发或所有工作流验收。
