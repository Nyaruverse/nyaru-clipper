## CONVENTIONS

- Operational edits must update both counterparts for deployment, operator, user, processing-flow, and wireframe docs.
- `deployment-guide*.md` is the fastest setup/run source of truth.
- `operator-manual*.md` owns production-safety boundaries: trusted LAN, no public internet, one worker.
- Document actual repo behavior from code/tests/scripts; do not import generic FastAPI/React norms unless this repo follows them.
- Check new workstation behavior against current routes and services; older manuals/wireframes may describe retained legacy screens.

## ANTI-PATTERNS

- Do not promote a historical plan/spec or investigation note to proof of shipped behavior.
- Do not describe mocked pipeline/browser tests as real GPU, download, or external-provider acceptance.
- Do not report a release smoke as passing without checking its selected test files exist.
- Do not translate only one side of a paired operational change.

## GENERATED / RUNTIME NOTES

- Requirements and OpenAPI artifacts have dedicated generators; see `scripts/AGENTS.md` from the repository root.
- `reports/task-report.md` is generated by the pipeline even when no clip is exported.
- Runtime artifacts live under `data/tasks/<task-id>/` with `raw/`, `work/`, `exports/`, `reports/`, and `logs/`.

## REVIEW CHECKLIST

- If a doc changes install/start/smoke commands, verify against `scripts/` and `infra/docker-compose.yml`.
- For stage/status/artifact behavior, check `backend/app/models.py`, service code, legacy shared types, and generated v2 schema.
- For UI behavior, check `web/src/router.tsx`, `web/src/workstation/`, shared review code, and actual `web/e2e/` scenarios.
