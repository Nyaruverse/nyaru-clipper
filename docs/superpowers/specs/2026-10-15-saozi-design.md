# 臊子：回放与 Bilibili 实时语义切片

日期：2026-10-15，Asia/Shanghai。状态：设计待确认，未实现。

## 已确认范围

功能名称为「臊子」。同时支持已结束的直播回放／本地录像，以及正在进行的 Bilibili 直播。实时模式只覆盖 Bilibili。

将整段可用内容连续分割为约 60–120 秒的切片，使用现有 DeepSeek Key 与模型分析字幕段落，优先在完整句、话题收束或自然停顿处切分。每片输出 MP4 与从零开始计时的 SRT，沿用现有预览、下载与字幕样式功能。

## 方案选择

推荐「连续录制 + 滚动字幕缓冲 + 语义切点」：录制与识别／分析分别工作，DeepSeek 选择尚未输出内容的下一处边界；同一套切点规则用于回放。能够在直播结束前输出结果，并用有限的后文帮助判断段落是否完整。

备选「先固定一分钟切片，再分析并合并」实现较快，但合并后可能超过两分钟，且初次切点容易落在句中；不作为交付方案。

## 输入与界面

- 在现有切片方式中增加「臊子」，包含「回放／本地录像」与「Bilibili 实时」两种输入。
- 回放使用现有 HTTP(S) 链接下载；本地录像通过文件选择导入到新的独立任务目录，保留原文件。
- 实时输入 Bilibili 直播间链接，显示录制、待分析、切片导出与处理积压状态，并提供「停止直播并导出剩余内容」。
- 未配置有效 DeepSeek Key 时在开始前提示；配置沿用现有持久化方式，不返回或记录 Key。
- 历史任务可区分臊子、指定片段和高光模式；既有模式与历史产物继续可用。

## 切点与内容连续性

- 从媒体起点连续覆盖至结束；不只挑选高光，不重复或跳过内容。
- 一般切片目标为 60–120 秒。提供候选字幕边界与少量后文，让 DeepSeek 返回候选边界标识、简短主题与切分理由；模型不生成任意时间戳。
- 本地验证模型响应的候选标识、范围、顺序及时间合法性，拒绝异常输出。字幕文字只作为数据，不执行其中的指令。
- 优先选择完整句末、段落收束和自然停顿；无法同时满足时长与句子完整性时，遵守 120 秒上限并明确标记边界受限，不能声称绝对语义保证。
- 小于一分钟的视频、直播停止或断流后不足一分钟的尾段允许单独导出，标明尾段；不能为了凑时长丢弃内容。
- 不识别出语音的区间保留视频并按时长切分，明确标记「无语音，按时长切分」，不伪称 DeepSeek 分析成功。
- API 错误、余额不足或非法响应保留原始录制与已完成结果，报告分析失败并支持重试；不静默改为固定时间切片。

## 回放流程

输入 → 导入／下载 → 本地识别 → 滚动窗口 DeepSeek 段落分析 → 校验并持久化切点 → 逐片导出 → 预览／下载。

识别缓存、语义分析检查点和已发布切片可恢复。缓存绑定源文件校验和、字幕、模型与提示版本，恢复不能重新选择已经发布的切点或覆盖既有不同产物。

## 实时流程与生命周期

解析 Bilibili 当前直播流 → 录制到短暂存块 → 仅处理已关闭且可读取的块 → 本地识别并拼接全局字幕时间轴 → 累积至少一分钟并预留少量后文 → DeepSeek 选择切点 → 导出并继续。

录制不等待识别或 DeepSeek 返回；处理慢时持续保存输入并显示积压。输出延迟包含等待足够内容、后文缓冲、识别、API 和编码，不承诺播放到第 120 秒时已经生成文件。

停止操作先终止录制进程并收束可用暂存块，再完成待处理内容与尾段。有限重连仍失败时结束当前录制会话并保留结果，清楚标明断流；不把网络缺失伪装成连续原始直播。重新启动直播录制需要明确操作，不在 App 重启后悄悄重新连接。

关闭 App 时清理录制子进程，保留已完成文件与待处理缓存；恢复只处理已有录制数据。保持单个处理任务和现有数据目录互斥机制，避免多个实例写同一任务。

## 验收

1. 回放和本地文件可创建臊子任务；连续时间覆盖、一般片长 60–120 秒、尾段规则和 SRT 零起点正确。
2. 用真实 FFmpeg 媒体验证切片时长、音视频可读性和字幕边界；用确定的段落样例验证 DeepSeek 候选选择及异常拒绝。
3. 实时源尚未结束时已经输出至少两个切片；停止后尾段导出，录制进程退出，已输出文件保持不变。
4. 覆盖断流、无语音、API 失败、恢复、慢处理积压和 App 退出；原有指定切片、高光、翻译与字幕样式回归通过。
5. 在浏览器及 macOS 界面操作新模式、查看进度、预览和导出；真实 DeepSeek 调用单独记录，模拟 API 不算真实服务验收。
6. Bilibili 真实直播接入单独记录实际可访问条件；可控测试流证明流式机制，不能代替站点接入验收。
